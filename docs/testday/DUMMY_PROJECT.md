# Dummy project for the phase-3 test day

Everything here is **synthetic**: colour bars and test patterns generated by ffmpeg. No client media, no client
project, no client project library. The generator never touches DaVinci Resolve (no scripting); the operator
imports the timelines in the Resolve UI. That keeps hazard A12 ("probe tools run on a client project") out of
the picture and means the scripting agent is the only Resolve scripting client on the machine during the test.

Tool: `testday/make_dummy_project.py` (Python 3.8+, stdlib only; ffmpeg for the media).

## 1. Make the media

```sh
python3 testday/make_dummy_project.py --out ~/ET_DUMMY_TESTDAY --dry-run --uhd   # plan, ffmpeg commands, disk estimate
python3 testday/make_dummy_project.py --out ~/ET_DUMMY_TESTDAY --uhd             # media + timelines (~25-30 GB with --uhd)
```

| Option | Default | Notes |
|---|---|---|
| `--fps` | 24 | 23.976, 24, 25, 29.97, 30. Set the Resolve project to the same rate and 1920x1080 **before** importing |
| `--codec` / `--profile` | ProRes 422 Proxy (`prores_ks -profile:v 0`) | ProRes decodes on Resolve Studio for macOS and Linux. `dnxhr` (LB) and `h264` also offered |
| `--uhd`, `--uhd-profile` | off, ProRes 422 | 60 s 4K and 8K sources + `PB_4K` / `PB_8K` playback timelines (2 min) for P1 |
| `--sources`, `--source-sec` | 24 × 30 s | Pattern sources; clips are 1–4 s cut from them at random in points (seed `--seed 26`, deterministic). The duration is set on the output (`-t`), files are written as `.part` and renamed when ffmpeg succeeds |
| `--font` | fontconfig | Burned-in label (`ET DUMMY SRC_007`) and source timecode via `drawtext`; skipped if the ffmpeg build has no drawtext |
| `--no-media` | | Only timelines + manifest (media made on another machine) |
| `--media-root` | `--out` | Where the media will live on the workstation (the XML holds absolute paths) |

**Where to run ffmpeg** (pick one, write it in the results):

1. **On a prep machine, then copy** (preferred: nothing is installed on the workstation). Generate with
   `--media-root` set to the final path on the workstation (for example `/Users/<user>/ET_DUMMY_TESTDAY`), copy
   the whole folder, check `MANIFEST.json` is there. If the path differs, re-run with `--no-media --out <copied
   folder>` on the workstation to rewrite only the XML.
2. **On the workstation with a static ffmpeg in the kit folder** (`~/ET_TESTDAY/kit/bin/ffmpeg`, pass
   `--ffmpeg`). Do not install ffmpeg with a package manager on the test machine: U1 compares the machine before
   and after, and a package install adds noise. Record the ffmpeg build and its SHA-256 in the results. On macOS a
   downloaded binary is quarantined: `xattr -d com.apple.quarantine ~/ET_TESTDAY/kit/bin/ffmpeg`.

Output folder:

```
ET_DUMMY_TESTDAY/
  MANIFEST.json            kit marker; the tool refuses to write into a non-empty folder without it
  REVISION_STEPS.txt       the R0-R9 steps below with exact clip positions (tick boxes)
  media/src/SRC_###.mov    pattern sources (testsrc2, smptehdbars, testsrc, smptebars, rgbtestsrc, yuvtestsrc, pal75bars, hue-shifted)
  media/vfx_v1/VFX_###.mov  12 "VFX" shots, version 1
  media/vfx_v2/VFX_###.mov  the same file names, different content (relink = replacement with grades kept)
  media/vfx_late/LATE_###.mov 10 shots that "arrive late"
  media/wc01/WC01_#.mov    the 6 + 2 clips of the 2026-10-14 replay
  media/uhd/UHD_4K.mov, UHD_8K.mov   (--uhd)
  timelines/*.xml          FCP7 XML (xmeml v5)  -> File > Import > Timeline...
  timelines/*.edl          CMX3600 EDL fallback (media must already be in the media pool); only for timelines
                           of <= 999 events (CMX3600 event numbers have 3 digits): not for T1500/T3000
```

Import in Resolve: **File → Import → Timeline…** → pick the `.xml` → tick *Automatically import source clips into
media pool*; leave sizing options at default. Import `T0030_v1` first as the check (2.5 in the checklist). If the
XML does not import on the version under test, use the `.edl` (import the `media/` folders into the media pool
first, then *Import → Timeline* with the EDL). Render preset for P3: render `T0300_v1` with a setting that takes
about 10 minutes on that machine with the agent OFF (for example ProRes 422 HQ at UHD with a noise-reduction
node); write the preset down and reuse it for all six runs, each to a new empty folder.

## 3. Revision scenarios (validate progress v2 while S1 runs)

Each step reproduces a worst case from `research/revision-worst-cases` (`docs/research/WORST_CASES.md`, WC ids)
on real Resolve, so phase 3 also checks the provisional, revision-aware progress (branch `night/progress-v2`).
All grading is done by hand in the Resolve UI. Positions refer to `T0300_v1` as imported; the cut (R5) comes after
every step that names positions. After each step wait **3 agent turns** (3 minutes) and write the step's
clock time in the results template.

PMS push is off in phase 3, and the server runs the progress-v2 engine only when a PMS progress path is set, so
the values are produced **afterwards, offline**: `testday/progress_replay.py` feeds the day's stored records
through the engine of a progress-v2 checkout with a fake PMS that only collects the bodies (no network), and
checks "never done/100 without a confirmed scope" and "every drop has an explaining reason". Match its output
times to the step times. (Checked on the build server against `night/progress-v2` c468881 with the real
2026-10-07..14 records: it prints exactly 16.67 → 99 (`mass_grade`) → 83.33 (`regression`) → 75
(`scope_change`), all provisional.)

| Step | Operator does (Resolve UI) | Worst case | Today's server (S0) would | Expected with progress v2 |
|---|---|---|---|---|
| R0 | Import `T0300_v1`, make it current | — | 0 % | `provisional: true`, 0 % |
| R1 | Grade clips 1–120 in 3 sessions of 40 (one serial node + any change), 10 min pause between | — | rises to 40 % | rises, provisional, never `done` |
| R2 | Import `media/vfx_late`, append the 10 clips to the end (Edit → Append at End of Timeline, Shift+F12) | WC02 VFX late, no placeholder | drop read as lost work | drop labelled `scope_change` |
| R3 | Grade the 12 VFX clips (positions 20, 43, …, 273), then relink them to `media/vfx_v2` (same names, grades kept) | WC07 new version, grade kept | may claim done | no jump to done, no unexplained drop (`replaced` only once the poller sends clip items) |
| R4 | Reset Grades and Nodes on clips 70–84, wait 3 turns, regrade them | WC09/WC10 regrade, rework | silent drop then back | drop labelled `rework` (or a regression with a reason), back up after |
| R5 | Ripple-delete graded clips 45–54 and ungraded clips 210–219 | WC05/WC06 shots cut | unexplained drop / jump | `scope_shrink`, labelled |
| R6 | One LUT / shared node on **all** clips | WC12 look on all clips | **100 % (false)** | not 100 %, not `done` (mass-grade guard) |
| R7 | Import `T0300_v2_reconform` as a new timeline, make it current | WC08/WC15 re-conform, new timeline | false 0 % or flapping | labelled change (`scope_change`, or a `reference_timeline` hold), no false 0/100 |
| R8 | `T0006_WC01`: grade clip 1; next turn all 6; next turn reset clip 6; then put `WC01_7`, `WC01_8` on V2 | WC01 exact 14 Oct replay | 16.7 → **100** → 83.3 → 75 | 16.67 → 99 (`mass_grade`) → 83.33 `regression` → 75 `scope_change`; never `done` |
| R9 | `T1500_v1`, `T3000_v1`: append 50 clips, wait 3 turns, ripple-delete 50 | scale | — | same reasons as R2/R5; `guard.ms` within the P2 budget; no `scan_budget` storm |

Reason codes and fields are those of `server/progress_v2.py` on branch `night/progress-v2` (c468881) and the
PMS contract v2 (`provisional`, `total_confirmed`, `done`, `done_count`, `total`, `reasons[]`): explaining codes
`scope_change`, `scope_shrink`, `rework`, `regression`, `replaced`, `reopened`, `scope_mismatch`, `job_mismatch`;
holds `detector_pending`, `reference_timeline`, `late_record`, `job_mismatch`, `no_data`; the provisional cap
is 99 (`EDITORTRACK_PROGRESS_CAP`). That branch is not merged yet: **before the test day, check the table against
the merged code** and correct it if names changed. PMS push stays off during phase 3: the values are read on the
editortrack server only.
